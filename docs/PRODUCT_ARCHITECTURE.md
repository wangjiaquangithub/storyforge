# StoryForge 产品架构

## 1. 产品定位

**目标用户**：职业网文作者、小型内容工作室  
**核心价值**：把长篇网文生产从"纯手工"升级为"AI 协作流水线"  
**差异化**：不是聊天机器人，不是单章生成器，而是项目驱动、资产驱动、可控的全流程工作台

---

## 2. 产品层级模型

```
Layer 5  —  交互层（Web UI / CLI）
Layer 4  —  API 层（FastAPI REST）
Layer 3  —  应用层（业务编排：ClosedLoopService）
Layer 2  —  执行层（LLM 调用 + 内容质量引擎）
Layer 1  —  领域层（Project / Asset / Task / Event / Config）
Layer 0  —  持久层（InMemory / SQLite）
```

---

## 3. 产品功能分层

### 3.1 核心层（生产流水线）

```
输入创意
  │
  ▼
┌─────────────────────────────────────────────┐
│  Brief 生成    │  作品定位、核心卖点、基调    │
├─────────────────────────────────────────────┤
│  Outline 生成  │  分章大纲 + 弧（Arc）结构    │
├─────────────────────────────────────────────┤
│  Chapter 生成  │  基于大纲逐章生成正文        │
├─────────────────────────────────────────────┤
│  Review 门控   │  质量审查 → 通过/拒绝重写  │
└─────────────────────────────────────────────┘
  │
  ▼
批量推进（写到第 N 章）
```

### 3.2 资产层（内容管理）

```
┌──────────────────────────────────────────────┐
│  资产类型                                     │
│  brief · outline · chapter · review_note      │
│  world · characters · rules · timeline        │
│  chapter_summary · continuity_note            │
├──────────────────────────────────────────────┤
│  版本追溯：每次编辑保存为新版本               │
│  乐观并发：base_version 防止覆盖              │
│  操作审计：actor_id / actor_name / change_note│
├──────────────────────────────────────────────┤
│  结构化数据：asset_type + content + JSON blob │
│  人类可读正文 + 机器可解析元数据              │
└──────────────────────────────────────────────┘
```

### 3.3 协作层

```
项目 → 协作者列表
  │
  ├── author（作者）：完整权限
  ├── editor（编辑）：编辑资产、保存版本
  └── viewer（观察者）：只读
  │
  └── 编辑操作记录 actor_id + change_note
```

### 3.4 导出层

```
导出格式：
  ├── Markdown（通用）
  ├── Plain Text（纯文本）
  ├── Qidian（起点格式：书名号 + 第N章）
  └── Jinjiang（晋江格式：【作品名】+ 【章节 N】）
```

### 3.5 可观测层

```
项目摘要：
  ├── 阶段、章节游标
  ├── 任务统计（总数/完成/运行/失败/等待/取消）
  ├── LLM 用量（total_tokens / input_tokens / output_tokens）
  ├── 最新事件消息
  └── 失败摘要（失败任务 ID、错误消息）

任务队列：
  ├── 状态：queued / running / completed / failed / waiting_retry / cancelled
  ├── 进度：0.0 → 1.0
  └── 步骤名：brief_generate / outline_generate / ...
```

## 4. 产品接口

| 接口 | 说明 |
|------|------|
| Web UI | 三栏创作工作台（项目列表 / 编辑器 / 辅助面板） |
| CLI | `storyforge create / start / status / chapters / loop / drain / read / serve` |
| REST API | 20+ 端点，覆盖项目/资产/任务/导出/协作全流程 |

---

## 5. LLM 集成

```
┌─────────────────────────────────────────┐
│  多 Provider 路由                         │
│  ├── Anthropic（Claude Sonnet 4.6）      │
│  ├── OpenAI                              │
│  └── 本地回退（STORYFORGE_SKIP_LLM=1）   │
├─────────────────────────────────────────┤
│  配置层级：系统默认 → 项目覆盖 → 任务快照 │
│  LLM 用量统计：每个任务记录 token 消耗    │
└─────────────────────────────────────────┘
```

---

## 6. 质量基础设施

```
ContentQualityEngine：
  ├── 结构检查：章节号、标题、摘要是否完整
  ├── 一致性检查：与 brief / outline 是否一致
  ├── A/B 实验：质量评分对比（预留接口）
  └── 本地回退评分：不依赖 LLM 的启发式规则
```

---

## 7. 产品边界

**包含**：
- 项目驱动的完整生成流水线
- 资产创建、编辑、版本追溯
- 多格式导出
- 协作者管理
- 质量审查与重写
- 任务状态追踪与队列处理

**不包含**（当前）：
- 实时协作编辑（Google Docs 式）
- 用户注册/登录/权限系统
- 云端存储/同步
- 图片/插画生成
- 读者反馈/数据分析
- 多语言翻译
